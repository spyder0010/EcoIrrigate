# Neural forecast-origin and TCN wording audit

**15 November 2026.** The saved neural results were checked against the supplied EcoIrrigate CSV, SHA-256 `1f12bac2a35f78b8f2c6af0fe56142f2301471d9ef2203a3983a5a60444d6319`. Run `python revision/audit_neural_ledger_against_source.py` from the workspace root. The deterministic output is `architecture_benchmark/neural_ledger_source_crosscheck.json`.

The audit joins every saved neural prediction origin and target to the source by site ID and exact timestamp. It checked **574,768 prediction rows in 16 ledgers**, covering the original common-origin comparison, additional seeds, no-auxiliary ablation and both rolling BiLSTM studies. Every saved horizon was exactly 1, 6, 12 or 24 hours, every current and target VWC matched the source within `5×10⁻⁶` VWC points, and no prediction origin or target fell outside its recorded final-test or rolling test block. The maximum absolute source differences were `0.000001080` for current VWC and `0.000001110` for target VWC, consistent with float32 serialization. Keys within each model/fold/seed/site/horizon had no duplicate origins.

The implementation additionally fits its feature scaler on the training segment only. `OriginDataset.__getitem__` supplies historical inputs from `t−96` through `t−1`, current sensor/environment and observed VWC at `t`, and future targets at `t+h`. The forecast head receives current VWC as the residual anchor; the auxiliary head does not receive current VWC directly. This code inspection supports the input-information description in the manuscript. The ledger check establishes saved-row alignment, not independent validation of model checkpoint weights, previously missing sensor logs, or physical VWC calibration.

One architecture label needed correction. `CausalBlock` left-pads its dilated convolution, but PyTorch `GroupNorm(4, 64)` normalizes over channels **and all 96 observed history positions** in each sample. An output at an earlier history position can therefore change if a later position inside the *already observed* history is changed. A direct perturbation check with a fixed random block changed an earlier output by `0.0100793` when only the final observed history step was changed. The block is not strictly causal at every intermediate position. The final context is taken at `t−1`, and the entire input window ends before the forecast origin, so this is a terminology/architecture-interpretation correction rather than evidence of future-target leakage. The manuscript and Fig. 1 now call it a **left-padded TCN** and describe the normalization explicitly. Existing checkpoints and scores were left intact.
